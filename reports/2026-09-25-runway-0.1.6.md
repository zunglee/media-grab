## 3. Found during integration

**Two segmented downloads starting together could fail: "The offscreen document did not respond."**
Chrome lists an offscreen document in `getContexts` as soon as `createDocument` starts, before its
script listens. A second `ensureDocument` saw the listing, returned, and sent work the document could
not yet receive ("Receiving end does not exist"). Latent since the offscreen document was introduced;
closing the document when idle (D16) made creation frequent enough for the split-stream test to hit
it. Found by adding `runtime.request` (which surfaces the browser's reason instead of swallowing it)
and an in-memory trace. Fix: wait for the creation in flight (`browser/webext.ts`); close and create
are serialized.

Also found and fixed: a played `<video>` and the request it made, claimed in one report, lost the
element's title and poster to the bare request (duplicate claims are now merged).

## 4. Evidence that the new tests test something

- **Against the 0.1.5 snapshot:** of the 15 new real-browser tests, 12 fail for the bug they target;
  the other 3 guard behaviour 0.1.5 already had ("paused survives a worker stop", "`#anchor` keeps
  media", "one `pushState` is one route").
- **Mutation checks:** each of the five durability restore rules and the duplicate-claim merge were
  reverted in turn; a test failed each time. Each engineer ran the same check on their own fixes.
- **Worker death is real:** the test stops the worker through the DevTools protocol and proves a new
  worker runs by a marker set in the old one.

## 5. Independent re-audit

Three reviewers who wrote none of the code, each with the 0.1.5 → 0.1.6 diff and the baseline tree:
durability and Referer (W2, W5, W8); saveability, "best" and navigation (W3, W4, W6); design and
documentation against D16–D21 and CHARTER. Every finding had to be reproduced (scratch unit tests
against the real modules) or quoted from the code; anything unproven was dropped.

| Severity | Found | What went wrong for a user |
|---|---|---|
| **High** | 1 | A download recovered after an extension update disappeared at the next worker restart: the saved queue left out tasks without an address, and the next worker trusted the empty copy. |
| Medium | 7 | A Referer rule outliving a cancelled task; a stop during Referer or offscreen setup not stopping the work (a Save dialog for a cancelled file, a whole stream fetched for nothing); "Allow ‹host›" lost across a worker restart; the durability tests unable to see a lost write (the fake storage aliased objects); a row marked saveable that failed on click; "Best" pairing an audio description or dub; `#!`/`#/` placeholder links wiping the page's media. |
| Low | 10 | Old rules cleared lazily; redirect hosts not covered; restore over the concurrency limit; a killed worker's offscreen leftovers; save gaps; rule breadth overstated in docs; hostnames with `_`; the wrong scheme checked; 401 in the docs; live HLS downloaded when undecided. |
| Docs | 4 High, ~25 Medium/Low | Two documents still described the in-memory queue; the durability contract promised a trace row the code does not keep; decision records not in the CHARTER form; counts, sizes and module names out of date. |

Accepted, not changed: one probed HLS rendition speaks for its ladder (stated in D21); a query-only
`pushState` stays a new route (decided in D17 — on many sites it is the next video).

Fixes were split: an engineer took saveability, "best" and navigation (disjoint files); the lead took
durability, Referer and the docs. Each behaviour fix has a regression test, and each was reverted to
prove its test fails — 28 mutations across the re-audit and verification fixes, all caught (the High has
two independent fixes, so it was proven by reverting both together). One fix has no unit test: the
offscreen document now tracks each task's attempt so an old one cannot remove a new one's cancel; that
module registers itself on import and needs a real document, so it rests on review and the
real-browser suite.

## 6. Verification round

The same three reviewers re-checked their own findings against the fixed tree.

| Reviewer | Result | New from the fixes |
|---|---|---|
| Durability and Referer | 11 of 14 fixed, 3 partly | 3 Low: a failure-safe save that rewrote the queue four times a second while storage was full; "shown once" no longer true; a stale trace able to bring a finished task back once |
| Saveability, best, navigation | 4 of 4 fixed | 3 Low residuals: audio-only rendition of an all-too-large ladder; no-Role DASH audio chosen by bitrate across languages; audio description signalled by DVB `Accessibility` or a spaced HLS tag |
| Design and docs | nearly all fixed | size units mixed (KiB and kB), one stale size block, cookie wording, the ceiling's new home, test tree and data model in the spec |

Closed after the round: the two partly-fixed code items (a stop during offscreen creation; refused
hosts across a worker restart), the save storm (one save at a time, a failed write retried after a
pause), the audio pairing residuals, and every doc item. Accepted and listed in `CONTEXT-RUNWAY.md` § 12:
the audio-only rendition of an all-too-large ladder; the queue's missing byte budget; a possible second
"Download complete" notification after a failed write (history de-duplicates by task id). The fixes made
after the round were checked once more by the two code reviewers: all confirmed, except one Low they
reproduced — a change landing a few microtasks after a save finished could wait for the next change;
fixed (the save clears its own "running" mark in the same step), with a test over every microtask
offset, mutation-checked. The saveability reviewer's last note (DVB commentary, AudioPurpose 3 and 4)
was closed the same way.

## 8. What is still true after this release

Watch items, all listed in README "Known limitations" or `CONTEXT-RUNWAY.md` § 12:

- Bundle headroom: the background bundle and the page hook are close to their budgets
  (PERFORMANCE.md); the next feature in either should remove something first.
- An HLS probe's saveability is applied to the whole ladder; estimated sizes use the average bitrate.
- The per-tab byte budget has no cross-tab total.
- One Referer rule per host: two tabs downloading from one CDN at once share the latest page's URL.
- Segmented downloads restart from zero after a worker restart (D16 option (d) not taken).
- Firefox has never been run (D19).

## 9. Release checklist (manual — the steps are in TESTING.md § 5)

Run by hand on the release build in Chrome before the release is called done. Automation cannot reach
these; the rest of the durability contract is covered by automated tests — in the real browser where
Chromium allows it, as unit tests elsewhere (`CONTEXT-RUNWAY.md` § 6.2 marks which).

1. Extension reload with a paused direct download: the row stays paused, without Retry; Resume
   finishes the same file.
2. Speculation Rules prerender, then activation: the target's media is listed only after activation.
3. The permission prompts: "Enable on this site", and "Allow ‹host› and retry" on a CDN that checks
   the Referer.
4. Late injection on a single-page app that has already changed route.
5. Assembly memory: the offscreen document at about one times the file's size, and gone afterwards.

## 10. Verdict

**Go** for 0.1.6 as a pre-alpha, Chromium-only release, once the five manual checks in § 9 pass on the
release build. Nothing blocking is open: every High and Medium the re-audit found is fixed, tested and
mutation-checked; the verification round's findings are fixed or accepted and listed; all automated
gates are green on the final tree, twice.

Not a go for: calling it a production downloader (README still says pre-alpha), Firefox (experimental,
D19), or adding features to the background or page hook without first making room (§ 8).
